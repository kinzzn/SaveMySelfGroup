# 术语与风格指南（Style Guide）

> 适用范围：BE:FIRST 访谈系列全书（含引言、成员个人访谈、后续增补章）的翻译（Translation）/ 编辑（Editing）/ 校对（Proofreading）。
>
> 目标：统一专名与术语、稳定采访叙事语感、保留成员个体人格与现场感，避免“日式直译腔”“网文夸饰腔”“公关稿平滑化”。

---

## 0. 全局执行原则（Global Principles）

1. **专名唯一制**：同一实体仅保留一个主译名（必要时首现并列原文）。
2. **语义优先于字面**：先还原说话意图，再落地为自然中文口语。
3. **采访体优先**：保留停顿、犹豫、自我修正、重复，不改写成“书面演讲稿”。
4. **人物区分必须可感知**：记者与成员、成员与成员之间语气不能混同。
5. **专业词不降级**：音乐制作/舞蹈术语保持行业精度，首现可做短注。
6. **时间轴一致**：围绕“2021 出道 → 4 周年 → 5 年目/5 周年节点 → 未来展望”统一表述。
7. **“真实感”高于“文采感”**：允许不那么工整，但必须像人在说话。

## 3. 文风与语气设定规范（Tone & Voice）

### 3.1 叙述层级：记者 vs 成员

1. **记者（小川智宏）**
   - 语感：观察细、逻辑推进强、常“先确认再追问”。
   - 中文落地：句子完整清晰，偏理性，不用网络化夸张词。
   - 常见结构：
     - `你刚才提到……这是否意味着……？`
     - `换句话说……可以这样理解吗？`

2. **成员回答**
   - 语感：口语、实时思考、边说边修正、常带笑场与自嘲。
   - 中文落地：短句+转折+停顿，允许“嗯、其实、怎么说呢”。
   - 禁止：过度抛光成“标准采访金句合集”。

### 3.2 成员个体语气画像（必须区分）

| 成员 | 原文语感 | 中文映射策略 |
|---|---|---|
| SOTA | 技术词密集、兴奋度高、节奏快、跨舞蹈与制作 | 用“专业+燃感”并行；术语可直给，句子不要太书面 |
| SHUNTO | 自省、讲分寸、强调控制与平衡 | 用词克制、逻辑清楚，少口号，多“我在调整” |
| MANATO | 结构化思维强、俯瞰团队机制、计划导向 | 语气稳、判断准，突出“策略视角/系统视角” |
| RYUHEI | 年轻但思辨强、野心感与探索欲并存 | 保留“少年感+野心感”；避免翻成成熟社论腔 |
| JUNON | 温和谦逊、聚焦“歌”、表达简洁 | 中文要干净笃定，少修饰，强调“声音与现场传达” |
| LEO | 外向热情与内在自我否定并存，反差强 | 保留“先自嘲后认真”的真诚转折，情绪起伏可见 |

### 3.3 口语标记词转换表

| 日文口语 | 推荐中文 | 禁忌 |
|---|---|---|
| めっちゃ | 特别 / 非常 / 真的很 | 全部译“超级” |
| マジで | 真的 / 说真的 | 频繁译“老实说” |
| 〜っすね / 〜ですね | 是啊 / 确实 / 我也是这么想 | 机械删除导致失真 |
| どうだろう | 这个嘛 / 不好说 | 硬译“如何呢” |
| 〜かな | 可能吧 / 我觉得 | 全删会丢失未定感 |
| いや | 不过 / 其实 / 倒也不是 | 全译“不是”显生硬 |
| うーん | 嗯…… / 这个…… | 直接删掉犹豫层 |

### 3.4 礼貌层与称呼

- 日文敬语不逐字迁移为中文敬语套话。
- 礼貌感通过“语气柔和+句式完整”体现，不堆叠“您/非常感谢您/请允许我”。
- 成员感谢场景可直译“谢谢/很感激”，非感谢场景不额外加礼貌词。

### 3.5 引语与情绪标记

- 直接引语统一全角引号「」。
- 重点语句可保留 **加粗**（对应原文强调）。
- （笑）（苦笑）（停顿）可保留，但仅在确实影响语气判断时使用。

## 4. 句法与版式规范（Syntax & Formatting）

1. **长句重组**：日文多层修饰按“主干 → 补充”拆译。
2. **主语补足**：对省略主语按语境补“我/我们/成员/团队/公司”。
3. **逻辑显化**：必要时补“所以/但/同时/换句话说”。
4. **并列对齐**：并列项词性一致（如“唱、跳、制作”）。
5. **标点统一**：中文全角标点；省略号“……”；破折号“——”。
6. **中英数字空格**：中文与英文/数字间留空格（如“5 周年”“World Tour”）。
7. **曲名与书名号**：作品统一《》；英文曲名保留大小写与标点本体。
8. **问答排版**：建议保留“● 提问 / 「回答」”结构，确保采访节奏可见。

## 5. 常见误译与风险点（Do / Don’t）

### 5.1 禁止项（Don’t）

1. 不将成员名汉化（如“俊斗”“怜欧”）。
2. 不把采访体改成新闻播报或品牌公关文。
3. 不把术语全部降维成泛词（如全部译“节奏”“感觉”）。
4. 不清洗全部口头禅（会丢人物识别度）。
5. 不过度文学化（比喻堆叠、抒情泛滥）。

### 5.2 必做项（Do）

1. 保留“自我修正”轨迹（如“也不是说……只是……”）。
2. 保留“反差人格”信息（尤其 LEO、SHUNTO、RYUHEI）。
3. 在技术段落维持术语密度（尤其 SOTA、制作相关段落）。
4. 将“抽象表达”落到可读中文，但不抹平抽象感。

## 6. 术语冲突裁决（Conflict Resolution）

出现多译法冲突时，按优先级决策：

1. 官方表记（艺名/团名/作品名）
2. 本指南既定译法
3. 音乐行业通行译法
4. 语境可读性最优解（并在首现加注）

## 7. 可复用执行模板（Operational Templates）

### 7.1 首次出现模板

- 人名首现：`LEO（上村礼王）`（仅在语义必要时）
- 术语首现：`DTM（电脑音乐制作）`
- 作品首现：`《WIND BREAKER/防风少年》`

### 7.2 记者追问模板

- `你刚提到……，那这是否意味着……？`
- `回头看当时的发言，你现在会怎么理解？`

### 7.3 成员口语承接模板

- `对，我现在会更……。`
- `也不是说完全……，但至少……。`
- `这个很难一句话说清，不过我会觉得……。`

## 8. 终稿质检清单（QA Checklist）

- [ ] 人名/团名/作品名是否全文 100% 一致
- [ ] 同一术语是否出现多种译法
- [ ] 记者与成员语气是否可一眼区分
- [ ] 六位成员语气是否各自可辨识
- [ ] 是否存在明显“日式被动句/长定语堆积”
- [ ] 是否误删关键口语标记（犹豫、转折、自嘲）
- [ ] 技术段落是否保持专业度而非被口水化
- [ ] 标点、空格、书名号、引号是否统一
